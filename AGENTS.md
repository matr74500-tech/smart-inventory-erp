## Architecture

- Employee page/action/field permissions live in employee_permissions; products are read only through visible_products, and database policies/triggers/RPC checks enforce access independently of UI visibility.
- Stock quantities change only through DB functions (set_stock, transfer_stock, receive_reorder) so every change is role-checked and logged in stock_movements.
- Login uses username mapped to a synthetic email (src/lib/arabic.ts usernameToEmail); roles live in user_roles and the first account becomes admin.
- Search normalizes Arabic letter forms client-side via normalizeArabic; inventory screens stay live through the realtime subscription in useInventory.
- Product codes (category prefix + sequence) and 628-prefixed EAN-13 custom barcodes are generated by the products_defaults DB trigger, so imports and manual entry share one numbering.
- Purchase invoices post through the post_purchase DB function, which adds stock, logs movements and updates cost/prices atomically.
- Product images are stored as small resized JPEG data URLs on the product row because public storage buckets are blocked in this workspace.
- Catalog PDF and barcode labels use the browser print dialog with print CSS (.no-print / .print-area) so Arabic text renders correctly.
- Admin user creation/password reset go through server functions in src/lib/users.functions.ts that verify the admin role before using the admin client.
